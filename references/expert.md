# 专家线：方法与知识配套

1. 定用途：同一本书服务决断和表达时是两次压缩；先界定待解决的任务。
2. 提炼思维：识别输入 → 选模式 → 检查前提 → 判断/行动 → 验证 → 失效降级。不要只写“深入分析”。
3. 配套知识：每个核心判断至少有可用的规则、定义、识别模式、案例或数据依据。
4. 模式卡按需使用：名称 / 可观察特征 / 规律或条件 / 操作 / 失效与降级 / 用户场景映射 / 来源。
5. 映射要具体：把“可信承诺”转成未来节点上是否仍有利益、违约成本、可撤回性等检查，而非重复术语。
6. 反查：执行每一步需要什么知识？这些知识在哪里？缺失时怎样继续或停止？
7. 精确参数、单位、公式适用条件不得只压成口诀；长资料随包，关键例外内嵌。
8. 默认编译 Skill，不要求人格、信念三条或 Lisp。用户指定 Prompt 也必须保留方法与知识。
9. 若来源是规范/政策，保留“必须/可以/禁止”区别；推断和建议不可伪装成原规定。
10. 混合线的角色只改变表达、注意偏好等允许变化，不覆盖专业证据与任务约束。
