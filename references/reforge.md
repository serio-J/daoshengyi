# 长材料分治与增量再铸（Reforge）

用于处理超出单次上下文的书籍/长文档/多源笔记，以及在已有产物（v1）基础上合入新材料升级到 v2。

---

## 一、长材料分治

不要按章节顺序做机械摘要再二次压缩（容易丢掉跨章节的隐藏变量与反例）。改按功能分治：

1. **先定锚**：先锁定用途、决策目标、关键失败条件与目标格式，再读材料。
2. **分块抽取候选结构**：按逻辑单元（主题/案例集/章节群）逐块扫描，只抽取四类内容：
   - 候选判断机制（触发条件 → 判断/动作 → 优先级）
   - 支撑知识（精确参数、定义、公式适用条件、关键案例）
   - 例外、反例与失效边界
   - 与前块可能冲突的表述（保留原出处定位）
3. **跨块聚合**：把所有块的抽取结果汇总到同一张轻量清单中合并重复；若出现跨块矛盾，按 `references/evidence.md` 的冲突排查协议处理（先查状态/范围/时间/视角差异，未解冲突显式保留）。
4. **再压缩与装载**：按 `references/workflow.md` 压缩；高频判断与不可丢边界内嵌热区，长案例与精确表格沉入冷区并写明读取时机。

---

## 二、增量再铸（Reforge：v1 + 新材料 → v2）

适用于「已有 Skill / Prompt + 新书、新笔记或实战纠偏」。

1. **判断是否属于 Reforge**：
   - 目标用途与核心锚点未变 → 走 **Reforge（再铸）**，保留原谱系；
   - 目标用途、受众或核心立场已根本改变 → 视为 **Fork（分叉）**，另起新产物或独立版本，不覆盖旧版。
2. **基线归档（可选）**：需要保留可回滚版本链时，先用 `scripts/archive.py` 为 v1 建立快照。
3. **差异分诊**：对照 v1 产物，把新材料逐条归入五类：
   - **重复/强化**：已有机制成立，仅补充出处或提高把握度，不膨胀正文；
   - **补缺口**：填补 v1 已声明的「待补证据/未知项」，并移除对应缺口提示；
   - **新增边界或例外**：为现有机制补充适用条件、失效信号或降级动作（对应 SPECIALIZE/SPLIT）；
   - **修订或冲突**：与 v1 既有规则矛盾；先核查是否因时间、版本或适用域变化导致（易变信息更新版本标注），真冲突时询问用户或显式保留分支条件；
   - **与当前锚点无关**：记录舍弃理由，不塞进产物。
4. **最小改动更新**：只修改受影响的机制、配套知识与边界，不推倒重写已稳定部分；在交付说明中简述本次相对 v1 的核心变更与被替代的旧规则。
5. **回归验证**：
   - 重跑 v1 原有的最小验证用例，确认旧边界与核心判断未退化；
   - 新增 1–2 条针对本次新材料/冲突点的验证用例；
   - 需要归档时，用 `scripts/archive.py` 记录 v2 快照与父版本关系。
