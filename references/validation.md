# 验证与能力保留

区分 structural_check、static_review、simulation、model_execution、human_approval。
不能通过字段齐全、结构检查、人工推演或合成结果宣称运行 PASS。

## 验证对象
专家：方法有知识支撑，识别条件正确，精确参数未丢，失效降级实际改变输出。
角色：驱动、反应、声音与知识边界一致；未知经历不编造，多轮关系变化不靠口癖代替。
混合：风格不推翻专业事实和关键边界。
所有格式：输出可独立使用，声明依赖真实，关键规则没有被格式转换丢掉。

## 案例
至少考虑普通、迁移、边界、缺输入、冲突、不适用场景；不适用项说明。
给独立执行者产物与任务，不给内部设计、预期答案或历史结论。
记录实际提示、实际输出、环境/方式、判据、失败和修复；只看可观察理由和行为，不索要隐私思维链。
没有独立执行环境时如实交付未运行验证候选版。
检查器测试不是道生一效果测试；单案例成功不是跨领域或跨平台认证。

## 对照
重要压缩任务尽可能比较相同执行环境下：
A 基础 Agent；B 原材料加任务；C 产物加任务。
预先保留未见测试，比较正确性、关键边界、知识遗漏、读取量与执行成本。
原材料过长无法公平对照时披露限制；不伪报压缩率或能力增益。
关键高损失规则不可被平均得分掩盖。

## 诊断
原材料缺依据 → 补材料/缩范围。
方法或知识错 → 修模型。
压缩遗漏 → 恢复区分。
产物没表达出来 → 修编译。
工具或运行环境不足 → 降级或报告依赖，不反改认知为环境找借口。
