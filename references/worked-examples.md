# 手艺样品：学操作，不套领域

以下均为新写的虚构教学例子，不是实测记录。样品只校方法与密度，不能套用领域结构。

## 专家：文件入库规则 → Skill
原材料：文件名需含项目号；无项目号退回补充；同项目同名但哈希不同需人工确认，不覆盖；相同哈希可判重复。
思维：先验项目号 → 比同名 → 比哈希 → 决定入库/补充/确认/重复。
知识：项目号定义、同名不等于同内容、哈希相同是本流程重复判据。
场景映射：新上传“报告.pdf”没有项目号时问项目号，不猜项目归属。
边界：没有哈希计算工具时不声称已判重复，要求提供哈希或人工核对。
成品片段：先检查项目号。缺失只要求补项目号。项目号存在后按同名与哈希分流；同名异哈希停止覆盖并请求确认。
压缩三问：去掉叙事保留四分支；删去无关上传历史；政策或哈希规则变化需重压。

## 角色：原创守塔人 → Prompt
用户设定：岚守雾塔，以船只安全优先；面对陌生人简短谨慎，对徒弟耐心；只知道岛上生活，不认识大陆王室。
思维：先辨是否影响航行安全，再看关系决定表达；未知大陆事件承认不知道。
知识：雾塔、岛、徒弟关系、知识地域范围。不得额外编造王室经历。
成品片段：你扮演原创守塔人岚。优先保障航船安全。陌生人问话简短谨慎，对徒弟解释原因。你只熟悉岛上生活，遇大陆王室问题不假装亲历；可创造当前对话，但不新增已发生的背景事实。
格式：一段自包含 Prompt 足够，不强制技能目录。
Lisp 变体：仅将上述驱动、关系、知识边界序列化为槽位；无解释器时标注“Lisp 风格提示词”。

## 混合
同一角色若负责按明确航行规则提供建议，规则与资料必须另行给足。
语气可以谨慎古朴，不能为了角色大胆或戏剧性而改变规则判定。
