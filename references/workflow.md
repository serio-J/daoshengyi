# 核心工作流：压缩、编译与验收

普通任务只需读本文件完成压缩、编译与验收；无需生成 CIR JSON、哈希清单或三档产物。

---

## 一、认知压缩（Compression）

在所有路线中，都必须同时保留**思维机制**与**配套知识**。压缩的目标是在保证生成保真度与边界保真度的前提下，最小化认知复杂度——最小的模型不是字数最少的模型。

内部维护一份轻量保留清单（`assets/retention-ledger.md`），必答三问：**为何这样压？丢了什么？何时需重压？** 并把规律映射到用户场景的可观察信号；精确事实移入可达资源，而非抽象成空泛口诀。

### 五种压缩操作
- **删除（DELETE）**：仅当反事实移除后，对目标相关的行为、边界、验证或重构均无实质差异时才删除。出现频率低不是删除理由。
- **合并（MERGE）**：仅当在所有相关状态下都不存在行为差异时才合并。只要任一状态会触发不同行为，就保留区分；语义相近不等于可合并。
- **拆分（SPLIT）**：当同一机制在不同条件下产生不兼容行为时，拆开它并寻找隐藏的区分变量。
- **泛化（GENERALIZE）**：仅当用一个共享的潜在因果规律替代多条表层规则，能降低复杂度、保留既有行为与边界、并提升新场景生成力时才泛化。
- **特化（SPECIALIZE）**：当某机制过宽时，补充条件、状态变量、边界或模式切换，而不是靠堆砌特例打补丁。

### 压缩误差、协同与停止规则
- **压缩误差**：指抹掉了未来需要用到的区分。典型症状：错误合并、丢失边界、优先级模糊、状态坍缩、丢弃稀有例外。
- **协同价值（Synergy）**：按条件组合评估信息价值，而非孤立评估；单条信息看似弱，组合后可能具有决定性区分力。
- **停止规则**：当预期复杂度下降小于预期在生成力、区分度、边界准确性或可审计性上的损失时，立即停止压缩。

## 二、编译（Compilation）

语义保留，格式可换。先按 `references/output-contract.md` 选择 Skill、Prompt、宿主角色卡或 Lisp。

- **轻量 vs 完整**：轻量模式只需内部保留清单，不生成 CIR 哈希或 `compile-manifest.json`。完整模式才记录 CIR 版本、映射和可选哈希，且这些属于设计档案，不是运行依赖。
- **语义映射**：
  - `Anchor` → 用途、范围、触发条件、输出格式
  - `W` → 配套知识、输入、实体、关系、世界/观察/信念差异
  - `Γ` → 条件、判断顺序、机制、动作与状态更新
  - `Boundary` → 澄清、降级、拒绝、升级、停止
  - `Evidence` → 必要来源与不确定性（不照搬全部原材料）
  - 角色 `Expression` → 语言风格（不得覆盖事实与专业规则）
- **档位控制**：默认只产出一个 Balanced（均衡）版本；仅在任务风险、运行能力、复杂度或预算确有需要时才采用 Loose/Strict，不自动生成三份。
- **热/冷装载与表达**：保留关键优先级、精确知识、边界与失效处理；可调整措辞、格式、例子和展开程度。资料由热转冷时必须检查「何时读取」与资源可达性，不得虚构工具接口。
- **重算与口吻**：上游状态变化后重算受影响部分；依赖不清时宁可重新核查，不假装已有准确依赖图。产物正文是对执行者的操作指令，不是对道生一建模过程的说明。

## 三、验证与能力保留（Validation）

严格区分五个验证层级：`structural_check`（结构检查）、`static_review`（静态审查）、`simulation`（人工推演）、`model_execution`（真实模型执行）、`human_approval`（人工审批）。**不能把字段齐全、结构检查、人工推演或合成样例写成运行 PASS。**

### 分线验证对象
- **专家线**：方法有知识支撑，识别条件准确，精确参数未丢，失效降级会真实改变输出。
- **角色线**：驱动、反应、声音与知识边界一致；未知经历不编造，多轮关系变化不靠口癖敷衍。
- **混合线**：表达风格不推翻专业事实与关键边界。
- **通用要求**：产物可独立使用，声明依赖真实，关键规则未在格式转换中丢失。

### 交付必带：最小验证用例（3–5 条）
每次编译交付时，在运行包之外默认附带 **3–5 条最小可执行验证用例**，方便用户或独立执行者直接验收，至少覆盖：
1. **典型任务**：验证核心判断/行为主链路是否按机制生成，而非泛泛而谈；
2. **边界/缺失输入/拒答**：验证触发边界时是否真的执行澄清、降级或拒绝；
3. **冲突或防 OOC 压力场景**：验证优先级仲裁、稀有例外，或角色在挑衅/越界下是否保持一致且不编造既成事实。

每条用例写明：**测试输入** + **预期观察到的边界/判断动作**（不泄露内部设计推导）。未实际运行前，只标注「待执行验证用例」，不得写 PASS。

### 独立执行与对照
- 给独立执行者产物与任务，不给内部设计、预期答案或历史结论；记录实际提示、实际输出、运行方式、判据、失败与修复（只看可观察理由与行为，不索要隐私思维链）。
- 重要压缩任务尽量在相同环境下对照 **A（基础 Agent）/ B（原材料 + 任务）/ C（产物 + 任务）**，预先保留未见测试，比较正确性、关键边界、知识遗漏、读取量与成本；原材料过长无法公平对照时如实披露限制，高损失规则不可被平均分掩盖。
- 没有独立执行环境时，如实交付「未运行验证候选版」。检查器测试不是效果测试，单案例成功不等于跨领域或跨平台认证。

### 因果诊断与修复
- 原材料缺依据 → 补材料或缩小范围；
- 方法或知识有误 → 修模型；
- 压缩丢了区分 → 恢复区分；
- 产物没表达出来 → 修编译；
- 工具或运行环境不足 → 降级或报告依赖，不反改认知为环境找借口。
